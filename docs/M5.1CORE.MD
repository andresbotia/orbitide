# WHY M5 EXISTS

The current game has 100 authored levels and a polished Pixel Arcadia UI, but real-device testing exposed a fundamental problem:

- gameplay is too easy to spam
- current perimeter/orbit behavior is not strategically meaningful
- pixels can be cleared too aggressively
- line-of-sight / occlusion is too permissive
- early levels remain simple too long
- the current circular arena wastes space
- 3 tunnels / 3 Holding slots limit future puzzle complexity

We are fixing the CORE GAME before economy/monetization work continues.

# ONE-PASS ORB LIFECYCLE

A launched orb receives:

ONE COMPLETE PERIMETER CIRCUIT.

During that circuit it may attack valid targets.

Each successful attack decreases its remaining count by exactly 1.

If remaining count reaches 0:

orb is consumed
active slot is freed

If it completes the full perimeter circuit and remaining count > 0:

orb moves into Holding

This rule is important.

Do NOT keep an unsuccessful orb circulating forever.

One launch/relaunch = one perimeter pass.

---

# TARGETING RULE

At its current perimeter position an orb fires inward.

It may attack ONLY:

THE FIRST ELIGIBLE TARGET ALONG ITS CURRENT ATTACK LINE.

Occupied geometry blocks targets behind it.

Example:

RED orb →

[RED A][RED B]

The orb hits RED A.

RED B becomes exposed.

The orb may NOT immediately drill through and hit RED B from the same firing opportunity.

It must continue around the perimeter and may only hit RED B on a later valid encounter.

# OCCLUSION

An occupied pixel in front of another pixel blocks the rear pixel from that attack line.

We need true geometry-aware targeting.

Audit the current exterior-flood-fill / reachability implementation and identify exactly how it differs.

We need to distinguish:

GLOBAL EXTERIOR REACHABILITY

from:

DIRECTIONAL VISIBILITY FROM THE CURRENT ORB POSITION.

# FIRING CADENCE

A successful shot is an EVENT.

A target must not be struck multiple times merely because the orb remains geometrically aligned over several render/update frames.

There must be deterministic protection against duplicate same-encounter hits.

A newly exposed rear pixel must not immediately chain in the same encounter.
