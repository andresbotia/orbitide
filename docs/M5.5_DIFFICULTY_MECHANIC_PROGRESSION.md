# PIXEL ARCADIA — M5.5
## Difficulty + Mechanic Progression Lock

### Task Type
Product / level-design specification.

This phase defines the difficulty model for Core Gameplay V2.

It does **not** implement solver changes.
It does **not** rebuild campaign levels yet.
It does **not** change engine rules.
It does **not** add economy/items/boosters.

This document becomes the design contract for:

- M5.6 — Solver / Authoring Pipeline V2
- M5.7 — Levels 1–10 Vertical Slice
- M5.9 — Campaign Rebuild

---

# 1. Core Difficulty Philosophy

Pixel Arcadia must become difficult because of:

- geometry
- line-of-sight
- tunnel sequencing
- limited future information
- Active-capacity pressure
- Holding pressure
- color distribution
- timing / pass order
- special mechanics
- multi-orb interaction

Difficulty must NOT rely primarily on:

- simply increasing pixel count
- making the board visually noisy
- hidden randomness
- impossible-to-read queues
- arbitrary failure states
- requiring boosters to solve authored campaign levels

Boosters/items may help later, but every authored campaign level must remain solvable without spending money.

---

# 2. Anti-Spam Rule

A level is not acceptably difficult if blind rapid tapping across all tunnels is a reliable winning strategy.

For Medium+ levels, the player should benefit from pausing to evaluate:

- which tunnel to advance
- whether the front charge can currently use its count effectively
- whether launching now will overflow Holding later
- whether another active Pal will expose a better line first
- whether a held Pal should be relaunched before advancing a queue
- whether queue order should be preserved for a later board state

For Hard and Super Hard levels:

> Blind tunnel spam must be a poor strategy and should commonly lead to inefficient Holding pressure, blocked sequencing, or loss.

This is a design-quality gate, not a runtime punishment.

---

# 3. Difficulty Labels

Use four gameplay labels.

## EASY
Purpose:
- readable
- low punishment
- obvious useful launches
- forgiving Holding/Active pressure

Player should usually solve on first attempt after understanding the rules.

## MEDIUM
Purpose:
- requires at least a few meaningful choices
- wrong order can create inefficiency
- recovery usually remains possible

Player should occasionally pause before launching.

## HARD
Purpose:
- launch order matters
- Holding pressure matters
- multiple plausible but suboptimal choices
- blind spam should usually fail or create a clearly worse position

Expected to require planning and sometimes a retry.

## SUPER HARD
Purpose:
- deliberate sequencing
- constrained Holding/Active resources
- combined mechanics
- narrow recovery windows
- strong geometry dependence

Must still be deterministic and fair.

Do not create artificial difficulty through unreadable UI or random outcomes.

# 4. First 10 Levels — Vertical Slice Difficulty

The first 10 Core V2 levels must reach real gameplay much faster than Legacy V1.

## Level 1 — Tutorial
Difficulty: Tutorial / Easy

Purpose:
- teach launch
- show perimeter movement
- show first-visible matching hit
- show count decrement
- force one incomplete lap into Holding
- teach tap-to-relaunch
- finish naturally

Restrictions:
- no special materials
- simple artwork
- minimal colors
- must satisfy M5.4 tutorial-authoring contract
- must not accidentally finish before Holding/relaunch occurs

## Level 2 — First Real Puzzle
Difficulty: Easy

Purpose:
- no tutorial chrome
- reinforce front-visible targeting through level geometry
- introduce meaningful choice between at least 2 useful tunnel fronts

Should feel like the real game immediately.

## Level 3 — Layering
Difficulty: Easy → Medium

Purpose:
- first board where clearing a front pixel exposes a rear target that cannot be immediately drilled
- require at least one later pass/revisit

## Level 4 — Queue Choice
Difficulty: Medium

Purpose:
- introduce 3rd tunnel if progression uses staged visibility/unlock
- make queue advancement meaningful
- wrong tunnel order should be noticeably less efficient

## Level 5 — Holding Pressure
Difficulty: Medium

Purpose:
- player should expect at least one Pal to enter Holding
- relaunch timing matters
- careless launches can consume 2–3 Holding slots

Legacy Level-21-like decision density should begin appearing around this point.

## Level 6 — Full Color/Queue Interaction
Difficulty: Medium

Purpose:
- 4 tunnels available
- more color variety
- overlapping useful choices
- at least one decision involving whether to advance a tunnel or relaunch Holding

## Level 7 — Active Capacity
Difficulty: Medium

Purpose:
- multiple simultaneous active Pals become strategically useful
- player should notice ACTIVE X/5 as a resource without a tutorial popup

## Level 8 — Dense Core Puzzle
Difficulty: Medium → Hard

Purpose:
- denser artwork
- 5–7 gameplay colors
- more complex directional exposure
- tunnel order matters over several moves

## Level 9 — First Hard
Difficulty: Hard

Purpose:
- first explicit Hard-level experience
- blind spam should commonly produce bad Holding pressure
- intended solution should include meaningful queue sequencing and relaunch decisions

## Level 10 — First Capstone
Difficulty: Hard

Purpose:
- combine all base Core V2 systems
- no special material mechanic yet unless explicitly approved later
- multiple simultaneous Pals
- real Holding pressure
- 4 tunnels
- deeper queues
- several geometry-dependent decisions

Level 10 should prove that the new core loop is substantially stronger than Legacy V1.

# 5. Tunnel Progression

Target final system: 4 tunnels.

For the first 10 levels:

- L1–L3: 2 active/usable tunnels is acceptable
- L4–L5: 3 active/usable tunnels
- L6 onward: all 4 tunnels

Implementation may keep all 4 physically present while unused/empty/locked lanes are visually subdued, if that is cleaner.

By Level 6, the player should be playing the normal 4-tunnel game.

Queue preview remains:

- Current
- Next
- Next+1

Deeper queue entries stay hidden.

---

# 6. Holding + Active Pressure

Default resources:

- Active capacity: 5
- Holding slots: 4

Difficulty should progressively use these resources.

### Early
L1–L3:
- 0–1 Holding slots typically occupied
- low Active pressure

### Developing
L4–L6:
- 1–2 Holding slots may be occupied
- multiple active Pals become useful

### Advanced first-world play
L7–L10:
- 2–4 Holding slots may become relevant
- reaching 4/4 Holding should be possible through bad sequencing
- Active 4/5 or 5/5 should occasionally matter

Do not require permanently filling Holding just to make a level look difficult.

---

# 7. Palette Variety

The campaign must stop feeling like the same 3–5 colors repeated.

Rules:

- each level receives an intentional palette subset from the full gameplay palette
- adjacent levels should avoid repeating the same dominant color combination
- world identity may influence mood, but gameplay colors must remain functionally distinct
- later levels may use larger color counts where artwork and readability support it

Suggested first-10 progression:

- L1: 2–3 colors
- L2: 3 colors
- L3: 3–4 colors
- L4: 4 colors
- L5: 4–5 colors
- L6: 5 colors
- L7: 5–6 colors
- L8: 5–7 colors
- L9: 6–7 colors
- L10: 6–8 colors

These are targets, not rigid requirements.

Authoring tools in M5.6 should be capable of detecting excessive adjacent-level palette repetition later.

---

# 8. Board Density / Size

Legacy max has historically been 28×28.

Core V2 should support denser artwork over time.

Do not blindly jump to huge boards in Levels 1–10.

Suggested progression:

### L1–L3
Small/medium readable boards.

### L4–L6
Moderate density.

### L7–L10
Clearly denser compositions, but still easy to read on-device.

Future campaign target:
- support approximately 32×32
- potentially 36×36 if device validation confirms performance/readability

By Level 50+, dense artwork may approach approximately 700–1000 occupied cells when appropriate.

This is a capability target, not a requirement for every level.

M5.8 device testing must validate performance before locking a higher board-size ceiling.

---

# 9. Core Geometry Rules for Difficulty

Level design must intentionally use Core V2 directional targeting.

Useful geometry patterns:

- front/rear stacks
- side exposure
- staggered columns
- recessed pockets
- narrow exposed edges
- shapes that become vulnerable from different perimeter segments over time

Avoid layouts where nearly every matching pixel is simultaneously available from many directions.

The player should sometimes need to:

1. clear a front layer
2. let the Pal continue around
3. expose a new line
4. hit that line on a later pass

This is central to Core V2 identity.

---

# 10. Special Mechanic Progression — Campaign-Level Plan

Do not introduce many special mechanics during the first 10 levels.

The base game must prove itself first.

Provisional rollout:

## Levels 1–10
Core systems only:
- directional targeting
- queue sequencing
- Holding
- relaunch
- Active capacity
- multi-orb play

## Levels 11–20
Base-system mastery:
- denser boards
- more colors
- stronger queue/geometry pressure
- no need to force a major new material immediately

## Levels 21–30
Frozen / Ice

Concept:
- first interaction breaks/weakens ice
- underlying pixel becomes normally clearable afterward

## Levels 31–40
Shielded

Concept:
- protective layer must be removed under its defined rule before normal clearing

## Levels 41–50
Armored / durability

Concept:
- multi-stage or multi-hit clearing

## Levels 51–60
Locked states

Concept:
- pixels or regions require an unlocking condition/order before normal interaction

## Levels 61–70
Geometry blockers / indestructible obstacles

Concept:
- cannot be cleared directly
- force around-the-side targeting and alternate attack lines

## Levels 71–80
Linked / conduit mechanics

Concept:
- interactions between paired/connected pieces

## Levels 81–90
Hidden / information mechanics

Concept:
- controlled uncertainty or masked state, while remaining fair and readable

## Levels 91–100
Mastery mix

Concept:
- combine previously taught systems
- capstone difficulty
- no brand-new major mechanic in the final stretch

This rollout is provisional until M5.6/M5.7 prove pacing.

# 11. One-Time Mechanic Tutorials

Core tutorial:
- Level 1 only

Future mechanics:
- one-time micro tutorial on first introduction
- short
- contextual
- no modal slideshow
- never repeat on every level using the mechanic

Examples:

Frozen:
`Break the ice first.`

Geometry blocker:
`This block can't be cleared. Attack around it.`

Copy should remain extremely short.

# 12. Difficulty Quality Gates

Before a level is accepted:

## Solvability
- deterministic winning witness exists
- no booster required

## Anti-Spam
- Hard/Super Hard should not be reliably beatable by blind tunnel tapping

## Meaningful Decisions
Medium+ should contain at least one real sequencing choice.

Hard+ should contain several.

## Holding Relevance
Holding should matter naturally where intended, not be artificially forced every level.

## Active Relevance
Later levels should sometimes benefit from multiple simultaneous Pals.

## Geometry Relevance
Core V2 levels must use directional visibility meaningfully.

## Queue Relevance
Visible look-ahead should matter to launch decisions.

## Readability
Difficulty must not come from unreadable colors or visual clutter.

## Fairness
Failure should be understandable in retrospect.

---

# 13. Suggested Authoring Metrics for M5.6

M5.6 should attempt to expose metrics such as:

- occupied cell count
- board density
- unique color count
- dominant palette distribution
- tunnel queue depth
- visible queue-front options
- number of Holding entries in witness
- maximum simultaneous Holding occupancy
- manual relaunch count
- maximum simultaneous Active count
- directional exposure / layer depth indicators
- number of meaningful tunnel-choice points
- witness length / action count
- color/palette similarity to adjacent levels

Do not treat one metric as “difficulty score truth.”

Difficulty is multi-factor.

---

# 14. Hard-Level Acceptance Test

A proposed Hard level should fail design review if:

- blind tunnel spam wins consistently
- Holding is irrelevant
- queue order barely matters
- nearly all targets are globally easy to access
- only pixel count makes it hard
- the witness is effectively “tap everything”
- visual readability is poor
- the level requires an item/booster

A good Hard level should create at least a few moments where an informed player pauses and makes a deliberate choice.

---

# 15. Super-Hard Philosophy

Super Hard is for later campaign use.

It may combine:

- near-full Holding pressure
- Active-capacity pressure
- deep queues
- incomplete queue information
- geometry blockers
- special materials
- color sequencing
- multi-orb timing

But it must remain:

- deterministic
- solvable
- readable
- fair
- possible without paid resources

Do not use Super Hard as an excuse for arbitrary punishment.

---

# 16. M5.7 Vertical Slice Acceptance Criteria

Levels 1–10 are not accepted as a vertical slice until:

1. L1 tutorial completes naturally.
2. L2 immediately feels like real gameplay.
3. By L5 the game already requires some thought.
4. L6 uses the normal 4-tunnel configuration.
5. L8 feels meaningfully denser/more strategic than L3.
6. L9 is the first true Hard level.
7. L10 is a convincing base-system capstone.
8. Blind spam is not a reliable strategy on L9–L10.
9. Palette combinations vary noticeably across the set.
10. Core V2 directional geometry matters in multiple levels.
11. No special mechanic is needed to fake difficulty.
12. All 10 levels have deterministic solvability witnesses after M5.6 tooling is ready.

---

# 17. Locked Decisions from M5.5

- Level 1 only is the basic-game tutorial.
- Level 2 starts real gameplay immediately.
- By Level 5, complexity should already be meaningfully above Legacy early-game pacing.
- 4 tunnels become normal by Level 6.
- Level 9 is the first Hard level.
- Level 10 is a Hard capstone.
- Base Core V2 mechanics carry Levels 1–10.
- New special mechanics are introduced later, one at a time.
- Hard levels must resist blind-spam play.
- Campaign levels remain solvable without boosters/items.
- Palette repetition must be actively controlled.
- Denser/larger boards are a future capability, subject to M5.8 device validation.
- M5.6 tooling must expose multi-factor difficulty/authoring metrics rather than one simplistic score.

---

M5.6 must update tooling so it understands:
