# M5.8B — Gameplay Release UI Spec

Status: implemented on `milestone/1-core-prototype` (uncommitted, for review).
Scope: gameplay **presentation** only. Engine, solver, FLFS, convoy/rail
geometry, campaign content, economy and progression are untouched.

Tokens live in `src/theme/gameplayUi.ts` (colour / surface / radius / type)
and `src/theme/gameplayMotion.ts` (durations, springs, thresholds — pure TS).
Reanimated builders that use them live in `src/components/gameplay/motionKit.ts`.
Nothing in gameplay chrome hand-rolls a colour, radius or duration any more.

---

## 1. Audit — what was inconsistent

| Area | Before | Problem |
|---|---|---|
| Colour | `NEON`, `material` (indigo/violet), `homeV2`, `arcade`, raw hexes all mixed | `material.textSecondary` (#ABA7D0) and `material.disabled` are lavender; `material.accentCyan` ≠ `NEON.cyan`; win sparks used brand orange `#FFB24D` instead of gold |
| Corners | HUD circles, wells 16, items 14, board 20, bays none, modal 22 | No family — circles next to squircles |
| Labels | ACTIVE 13/600, HOLDING 10/700 1.8 tracking, status 11 | Two status readouts, two type scales, on two rows |
| Press | `Pressable` `pressed` style (JS re-render) on HUD/items/wells; tunnels mixed | Press response waits a React commit; inconsistent depth |
| Tunnels | Pal + faint pedestal, queue chips hard-swap on advance, new ready Pal fades in | No physical bay; queue advance is a swap, not a movement |
| Refusals | Tunnel shake identical for "rail full" and "no targets" | Implies capacity when that is not the reason |
| Gate | Static Skia ring, no response to anything | The one physical gameplay object with three meanings never reacts |
| Hits | Streak + flash + core; count digit changes silently | Count decrement has no beat of its own; no sense of momentum |
| Holding full | Label turns red | Nothing on the tray itself |
| Win | Picture reappears as a 34 % ghost, then a trace over it | The player never actually sees the finished artwork |
| Loss | Red Pal icon, red 28pt title, zoom-spring card | Reads punitive / cheap spring |
| Next level | Hard cut from win screen to intro card | Visible discontinuity |
| Items | `scanner` still in the placeholder rack | Scanner was removed from the tool direction |

## 2. Hierarchy (unchanged structure, sharper weighting)

```
HUD (44pt)            [LV chip] [progress ───────── %] [home][restart]
BOARD                 art + rounded rail + GateTerminal (bottom-centre)
DECK  status strip    ACTIVE ▮▮▮▯▯ 3/5              HOLDING 1/3
      Holding wells   [ ][ ][ ]
      Tunnels         [bay][bay][bay][bay]   ready Pal + next + next+1
      Items           [undo] [+slot] [bomb]
```

ACTIVE moved from its own deck row into a single **status strip** shared with
HOLDING. Both pressure readouts now sit together directly above the controls
that change them, and the deck lost one 20pt row (board grows by that much).
No element changed zone.

## 3. Colour usage

- **Navy ink** (`GP.canvas / deck / panel / well / wellDeep`) — every surface.
  Surfaces never carry hue; gameplay colours dominate.
- **Cyan `#22E6FF`** — the system's "live / yours / go" colour: progress, ACTIVE
  pips, occupied wells, launch energy, gate transit, primary hairlines.
- **Gold `#FFC94D`** — reward and pressure-that-isn't-failure: full ACTIVE,
  last Holding slot, capture at the Gate, combo ≥ 10, completion, win.
- **Magenta `#FF2E88`** — reserved accent (combo chip edge at high chains only).
- **Danger `#FF4D6A`** — refusals, Holding FULL, reject, loss chip. Never a fill
  larger than a chip; never full-screen.
- No purple/violet/lavender anywhere in gameplay (material's indigo text roles
  are no longer used by gameplay components).

| `radius.control` | 12 | HUD buttons, LV chip |

| Hairline strong | cyan 0.32 | occupied / interactive borders |

Type: `label` 10/800/1.6 tracking (ACTIVE, HOLDING, LV); `numeral` tabular
13/800; `display` Space Grotesk 700 (LV number, LEVEL FAILED, intro title,
combo). No shadows on text except the resting Pal badge outline.

## 5. Pal treatment (identity unchanged)

Shell / visor / eyes / external lower-right badge unchanged. Additions:
- Badge **tick**: the count plate pops 1 → 1.22 → 1 over 150 ms on every hit,
  on the same frame the digit changes (UI thread, from the pass clock).
- **Launch trail**: during the lift only, a short Pal-coloured streak behind
  the shell (one view per flight), gone by rail entry.
- New `down` mood (flat eyes) — used only by the loss card.

## 6. Tunnels

- Each tunnel is a recessed **bay** (well fill, hairline, radius 16) with a
  cyan **lip** on its top edge (the launch direction).
- **Press**: UI-thread depth — bay compresses (scale .95, +1.5pt) in 55 ms on
  touch-down, springs back on release.
- **Accepted**: lip flashes cyan (rise 50 / fall 220), bay rebounds (lift −3pt,
  spring), the next Pal **slides up** from the queue into the seat (scale
  queue→ready, spring), queue chips slide up one slot, the new last chip
  fades/scales in. No hard swap.
- **Denied, ACTIVE full**: firm shake (±4pt) + lip flashes danger. ACTIVE strip
  pulses red 1.14× (unchanged behaviour), Error haptic (unchanged throttle).
- **Denied, other reason**: soft shake (±2pt), lip flashes muted cyan; no red.
- Blocked (rail full): bay dims to 0.78 and the lip greys — still pressable.

## 7. Active rail / launch / Gate

Rail geometry, lanes, convoy holds, staging-upstream entry and all engine
timestamps are untouched. Presentation added **per flight, driven by the
flight's own clock** (no JS, no new timers):

- Gate **transit** (every launch, at rail entry): cyan ring 0.7→1.7, 260 ms.
- Gate **capture** (toHolding, at lap end): gold outer + cyan inner ring, 320 ms.
- Gate **reject** (at the burst): danger ring 0.8→2.3 + core flash, 360 ms,
  alongside the existing board-edge `RejectPulse`.
- No idle animation on the Gate.

## 8. Hit language

anticipation (engine 20 ms) → streak (Pal colour, bright head) → impact
(white core + colour ring, unchanged) → pixel pop (unchanged) → count tick.
Effects stay at a fixed 3 views per flight no matter how dense the board is.
P2-F (unified popping-pixel layer) not needed — see perf report.

### Combo / momentum

Board-level UI-thread state (`chain`, `lastHitAt`, `energy`), fed by each
flight's animated reaction when one of its shots clears — zero JS per hit.
- Hits ≤ 360 ms apart extend the chain (across all Pals).
- Chain ≥ 3: board-edge energy pulse, cyan, scaled by chain.
- Chain ≥ 6: small **COMBO ×N** chip on the top rail band (never over art).
- Chain ≥ 10: edge and chip turn gold.
- Sound hook `combo` fires once per tier crossing (6/10/20) — audio-ready.
- Haptics unchanged: the arbiter already escalates grouped hits pop → combo → burst.

## 9. Holding

- Status: HOLDING n/cap in the strip. Tiers: calm (muted) → occupied (cyan) →
  last slot (gold) → **FULL** (danger chip).
- Wells: last free well rim turns gold at the warning tier; at FULL every well
  rim turns danger 0.45 (static — no flashing).
- **Capture**: gold→cyan ring expands from the well + well dips .94→1 (spring).
- **Relaunch**: cyan release ring + well dip; the flight takes off from the slot.
- Reshuffle: 160 ms ease-out slide (unchanged). Press: UI-thread depth.

## 10. Booster deck

Undo / Extra Slot / Bomb (placeholders, no gameplay action — scanner removed).
58pt bays, radius 16, locally drawn glyphs, gold-rim quantity badge.
Press: depth .92 + border brightens; release: cyan activation ring. Empty:
dashed rim, faint glyph, soft shake, no haptic.

## 11. Win language (logical timing untouched)

final hit → gold final-clear flash (existing) → engine win beat (+~380 ms, unchanged) →

| t (ms) | Beat |
|---|---|
| 0–440 | **Artwork restored**: the finished picture (same renderer as play) wipes in bottom→top behind a gold scanline |
| 380–1000 | Gold board-edge pulse; HUD progress fill turns gold |
| 560–960 | Restoration nodes rise |
| 700–1180 | Trace draws |
| 900–1200 | Title resolves; success haptic |
| 1150 / 1400 | NEXT visible / pressable |
| → 3200 | Sparks (gold/cyan, ≤ 8/14/20 by tier); art settles to 85 % |

The completed artwork is visible at full strength for ~0.9 s before any text
appears and is never covered (the panel sits below the board).

## 12. Loss language

reject → Gate danger burst + board-edge pulse (existing) → fail beat (unchanged)
→ board dims (300 ms) → card rises 18pt + fades (no zoom spring).
Card: navy panel, thin danger top edge, Pal with `down` eyes, **LEVEL FAILED**
(light text, not red), danger reason chip (HOLDING FULL / NO MOVES LEFT),
one-line explanation, dominant **TRY AGAIN** (primary CTA), Home text button.
Retry: board re-arms (dim fades out, board settles .97→1 in 220 ms).

## 13. Intro / next level

- Intro card content rises 8pt + fades in (160 ms) on an already-opaque navy
  field — the board is never visible while unpainted.
- When gameplay is ready the card fades (200 ms) while the board settles .985→1.
- NEXT: the screen fades to navy (160 ms) **before** navigating, so win → intro
  → board is one continuous navy field (no hard cut, no white flash).

## 14. Tutorial

Logic untouched. Coach callout: panel fill, cyan lit edge, 12pt text (was
10.5), enters with a 6pt drop + fade. Spotlight rings: 2pt cyan + soft outer
ring, same 900 ms UI-thread breathe.

## 15. Motion rules

Every gameplay animation is Reanimated UI-thread (shared values, transforms,
opacity, `interpolateColor` on small views) or Skia. Per-hit work never runs in
JS. Pattern is **action → response → settle**; there is no new ambient loop.
The frozen background glow stays frozen.

## 16. Reduced motion

| Effect | Reduced motion |
|---|---|
| Press depth | kept (it is feedback, not decoration) at half travel |
| Queue slide / ready slide | 90 ms fade instead of travel |
| Bay rebound, well dip, arrival bounce | off |
| Refusal shake | replaced by the lip/strip colour flash only |
| ACTIVE refusal | colour flash kept, no scale |
| Gate rings | opacity only, no scale |
| Launch trail, badge tick scale | off (digit still changes on the beat) |
| Combo edge / chip | chip shown without scale; edge pulse off |
| Win | wipe → 160 ms fade; scanline, sparks off; REDUCED reveal timeline |
| Loss card | fade only |
| Board entry / exit fade | 90 ms fades |

Required physical positioning (flight path, Holding landing) is never removed.

## 17. Audio map (hooks exist, no assets)

loss → `fail` · booster → (placeholder, none).
